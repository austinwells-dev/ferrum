## Initial design evidence

Ferrum already shares embedding, linear, SwiGLU, RMSNorm, RoPE, attention, KV storage, generation, sampling, and packed quantized math. `src/model/qwen.rs`, `qwen_gguf.rs`, and `qwen_mlx.rs` are strict Qwen2-specific adapters. The current `ModelConfig` captures common dimensions, while `DecoderLayer` and `Attention` assume one pre-attention RMSNorm, one post-attention RMSNorm, full attention, and no per-head Q/K normalization. The first policy extension will cover observed Qwen2/Qwen3 differences only; the existing Qwen2 contract must remain the default for current tests and format adapters.

Safetensors file loading now parses and validates the bounded JSON header, checks the public safetensors `Metadata` range/shape validation and exact file length, then streams tensors in offset order directly into their final Metal shared allocations. This avoids holding a complete checkpoint byte vector alongside the model on the host; malformed and truncated files still reject. `from_bytes` remains available for in-memory fixtures and serialized inputs. The implementation uses safe Rust and does not memory-map model files.

The official Transformers 4.57.6 `modeling_qwen3.py` installed in `.venv-reference` applies `q_norm` and `k_norm` after projection and reshape to `[batch, sequence, heads, head_dim]`, before RoPE. The current Ferrum RMSNorm kernel reduces over the last dimension and can implement that operation without new model-specific math.

## Dense milestone 1: shared Q/K policy and Qwen3

The first policy adds per-head Q/K RMS normalization and a Q/K/V bias requirement, selected at construction. The existing transformer, attention kernels, Metal device, KV cache, SwiGLU, generation, and sampler remain shared. Qwen2 retains its previous default execution path; the Qwen3 adapter validates config and maps official names into canonical weights. The official Qwen3 safetensors checkpoints serialize a duplicate tied LM head; the loader validates byte equality and retains only one copy in the model. A general indexed-safetensors directory loader checks every shard assignment, tensor name, total byte count, and shard filename.

The reference is local Transformers 4.57.6 / PyTorch 2.8.0 on CPU, using the same official checkpoint and exact prompt IDs. `tools/reference_causal.py` and the four JSON files under `docs/measurements/phase6/` retain reference IDs and top-ten logits for the 0.6B and 1.7B Hello prompt plus 2-token and 121-token 0.6B prefill cases. Ferrum matched all eight greedy IDs for each case. Maximum absolute difference over reference top-ten logits was 0.1875 (2-token prefill), 0.5 (21-token 0.6B), 0.3125 (121-token prefill), and 0.6875 (21-token 1.7B). The test bound is 1.0 for these BF16 comparisons. Snapshot branches reproduced byte-identical logits; reset and re-prefill reproduced the first greedy token. The real-model tests ran with Metal API and GPU shader validation enabled.

The Qwen3 GGUF adapter reuses the same policy and native packed Q8_0 kernels; it reads `qwen3.*` metadata and maps the added Q/K norms. Official Q8_0 and BF16 produced identical eight-token greedy IDs on the 21-token prompt. Minimum full-vocabulary Q8/BF16 logit cosine across those eight steps was 0.998014. ## Dense milestone 2: Granite 4 and OLMo 2

The official [Granite 4.0 350M checkpoint](https://huggingface.co/ibm-granite/granite-4.0-350m/tree/bd8a1497065c0d6ba1ef19af6b0d2b14bacf71c2) is revision `bd8a1497065c0d6ba1ef19af6b0d2b14bacf71c2`, Apache-2.0, with `model.safetensors` SHA-256 `21bc1ccaf0eb6a8a503addd93cb7422df71129de0a641a5525e4a665813b6dfc`. Although its architecture identifier is `granitemoehybrid`, its 28 declared layers are all attention and both expert counts are zero. This checkpoint is therefore a **dense** validation target; it is not evidence of MoE or recurrent-state support. Its 226 BF16 tensors contain 352,379,904 parameters. Each shared MLP packs gate/up rows in one tensor; the adapter maps two checked contiguous views without a payload copy. Official Transformers equations require embedding multiplier 12, attention scale 0.015625, residual multiplier 0.263, and logit divisor 4. The loader rejects checkpoints that enable experts or Mamba layers.

The official [OLMo 2 0425 1B checkpoint](https://huggingface.co/allenai/OLMo-2-0425-1B/tree/a1847dff35000b4271fa70afc5db10fd29fedbdf) is revision `a1847dff35000b4271fa70afc5db10fd29fedbdf`, Apache-2.0, with F32 safetensors shards SHA-256 `c52e4ac8bf4867e698d908f9e8c2b84aa891b91dff066d46bf2a7cf453ad77fb` and `5f80762572fe28aca49b01b98895d96ca529b9792fc10925a977a161ad768d30`. Its 179 tensors contain 1,484,916,736 parameters. OLMo 2 applies Q/K RMSNorm across each complete projected vector **before** head reshape, then normalizes attention and MLP outputs **before** adding each residual. Ferrum uses the same attention, MLP, norm, KV, and generation primitives with an explicit Q/K layout and residual topology policy. The checkpoint has an untied LM head and 16 Q and 16 KV heads, unlike Granite's 16/4 GQA and Qwen3's 16/8 GQA.

The authoritative implementations inspected were [Transformers GraniteMoeHybrid](https://github.com/huggingface/transformers/blob/main/src/transformers/models/granitemoehybrid/modeling_granitemoehybrid.py) and [Transformers OLMo2](https://github.com/huggingface/transformers/blob/main/src/transformers/models/olmo2/modeling_olmo2.py). Ferrum compares exact official-tokenizer prompt IDs to local Transformers 4.57.6 / PyTorch 2.8 references. Four reference JSON files record 2-token and 25-token prompts, eight or four greedy steps, top-ten logits, and framework versions. Granite matched every greedy ID; its maximum selected top-ten logit difference on the short case was 0.125. OLMo 2 matched every greedy ID; its short-case maximum difference was 0.0000252 after the F32 vector projection path. Both models passed cache branch replay and reset checks. All tests ran with Metal API and GPU shader validation enabled. The Granite Transformers checkpoint needs an explicitly initialized hybrid cache to return cached state; its reference tool therefore recomputes the full prefix each step, while Ferrum's verified attention-only KV cache decodes incrementally. OLMo 2 uses ordinary reference KV caching.

OLMo 2 initially fell onto the scalar F32 matrix projection, producing about 2.2 cached tokens/s. Extending the existing aligned vector and split-K GEMV kernels to F32, and dispatching small F32 prefills as batched GEMVs, preserved numerical agreement while improving diagnostic cached decode to about 19.2 tokens/s and 25-token prefill to about 46.1 tokens/s. Focused F32 tests cover vector alignment fallback, output tails, K splits, and batch lengths 2, 8, and 21 under Metal validation. This is a reasonable production path for the selected model; larger F32 prefill remains less optimized than BF16 native matrix execution.

## Sparse MoE milestone: Granite 3.1

The selected [Granite 3.1 1B-A400M Instruct](https://huggingface.co/ibm-granite/granite-3.1-1b-a400m-instruct/tree/0da7a48b0276d500ce5922fd2b33944091fc6c09) checkpoint is official Apache-2.0 BF16, revision `0da7a48b0276d500ce5922fd2b33944091fc6c09`. It has 1,334,628,352 parameters across 218 tensors (2,669,256,704 payload bytes). Its config selects 8 of 32 experts per token. The adapter maps official router and expert tensors into the shared decoder and sparse MLP runtime; no model-specific Metal runtime or expert kernels were added.

Routing computes the router projection over all tokens in a chunk, synchronizes at the data-dependent host selection boundary, selects top-k experts and normalized weights, then launches grouped assignment and expert input/output projections for all assignments. Expert and token IDs are stored as exact `u32` bit patterns in F32 metadata, avoiding low-precision index truncation. Temporary routing is chunked under a 16 MiB bound. A 300-token synthetic test exercises IDs beyond the earlier 8-bit failure boundary, odd hidden/intermediate widths, and CPU numerical comparison.

The authoritative source is [Transformers GraniteMoe](https://github.com/huggingface/transformers/blob/main/src/transformers/models/granitemoe/modeling_granitemoe.py). Local Transformers 5.2.0 / PyTorch 2.8.0 generated the reference using the same official weights and tokenizer. The real checkpoint test matches all eight greedy IDs; maximum absolute error across recorded top-ten logits was 0.375 (test limit 1.0). It also passes the 321-token two-chunk prefill comparison, cache branch equality, reset/re-prefill replay, expert-visit accounting, and temporary-memory bound. Both the real test and focused 300-token test passed with Metal API Validation and GPU Shader Validation enabled.

The custom expert projection initially used the wrong buffer index when registering its output with Ferrum's completion tracker. The dispatch contract now records explicit input/output counts per built-in kernel and marks every output range; an injected failed-completion test verifies that the actual expert projection output cannot be read. No unsafe Rust was introduced.

### Hybrid plus MoE integration

The official [LiquidAI/LFM2.5-8B-A1B](https://huggingface.co/LiquidAI/LFM2.5-8B-A1B/tree/5dd22602c2e9f6a097b1de4c4efe0658b605015c) was loaded at the pinned revision on the Apple M5. It has 24 layers: 18 causal-convolution blocks and 6 full-attention blocks; its first two MLPs are dense and the next 22 use 4 of 32 experts. The 2,302 checkpoint tensors contain 8,467,856,128 parameters; source and retained model weights are each 16,935,715,072 B. The context policy caps the config's 128K declaration at the model card's documented 32K. The tokenizer has 125,017 IDs and the model matrices have 128,000 rows.

The F32 expert-bias vectors are learned checkpoint data, not zero values: all 704 entries across 22 layers are nonzero. The loader validates each vector's F32 dtype and 32-element shape, preserves it in the shared MoE routing policy, and uses `sigmoid(logit) + expert_bias` to order top-k experts. Selected route weights come from the un-biased sigmoid values, then use the configured top-k normalization and scaling. Per-expert W1/W3/W2 tensors are packed losslessly into shared grouped weights one layer at a time; their source tensors are removed as each layer is packed.

The Transformers 5.2.0 / PyTorch 2.8.0 CPU reference and Ferrum used the same 11-token ChatML prompt and pinned checkpoint. Ferrum matched all eight greedy IDs; maximum absolute difference among the reference top-ten logits was 3.0 (test limit 3.25). The test verifies the 2,302-tensor and parameter counts, tokenizer IDs, hybrid cache/state size, 1,584 routed assignments, branch replay, and reset/re-prefill. Metal API Validation and GPU Shader Validation were enabled for the real-model test. A routing unit test confirms that expert bias changes selection without being added to the selected probability weights.

## Phase 6 closeout

The shared `ArchitecturePolicy` now composes per-layer attention or causal short convolution with dense or sparse feed-forward policies. Model adapters validate config and tokenizer metadata, map official names, and select shared primitives. Sparse routing supports softmax or sigmoid scores, learned selection bias, top-k normalization/scaling, grouped expert execution, and bounded temporary storage. The safetensors path validates bounded headers/ranges/file lengths and streams each tensor into its final Metal allocation; LFM2-MoE packing releases source expert tensors as it proceeds. The shared cache stores per-layer KV or convolution state, branches through immutable snapshots, stages updates until Metal completion, and supports reset and retry without publishing failed state. Qwen2.5 dense/quantized formats continue to use their prior adapters and kernels.

### Remaining limits and handoff

Validated hybrid context is capped at 32K; long-context quality/performance and LFM2.5-8B-A1B prompts above the 11-token reference are untested. Q4_K_M generation is validated and profiled at batch 1, but its quantized expert dispatch has not been profiled at larger batches. The current MoE runtime gathers router logits on the CPU at a synchronization boundary; routing-boundary wait dominated both cold 8B profiles. Ferrum does not support shared experts, Gated DeltaNet, multimodal vision/audio, MTP, paged attention, or Qwen3.8. No public official Qwen4 checkpoint was found in the current [Qwen organization model listing](https://huggingface.co/Qwen/models). Official [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) is 27B parameters and its published 64-layer schedule interleaves three Gated DeltaNet blocks with one gated-attention block; it also includes a vision encoder and MTP. Its BF16 weights alone exceed this host's recommended working set, and its non-LFM recurrent semantics are not implemented. No Qwen3.8 or Qwen4 support claim is made.

No new unsafe Rust was introduced. The real model tests exercised the shared allocation, packed expert weights, Metal completion tracking, cache branch/reset, and output paths under API and shader validation. The checked loader and existing transactional failure/retry tests passed in the final suite. A strict BF16 rounding experiment for sigmoid routes was rejected: it changed the final greedy ID on the official 8B reference, while the measured F32 host route calculation matched all eight reference IDs. Phase 5.5 remains explicitly performance-incomplete; the recommended follow-up is a separately scoped performance phase focused on router synchronization, large expert GEMM/GEMV, and measured peak memory, not an automatic expansion of architecture support.
